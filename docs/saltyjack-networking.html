SaltyJack networking

Station mode, the SoftAP named POSEIDON-SaltyJack, the W5500 pinout, and the ESP32-C5. What this tree actually runs, and what it does not.

Authorized use only

Run these tools on networks and hardware you own, or where you have explicit written permission. DHCP starvation and rogue DHCP disrupt address assignment. Responder and WPAD collect authentication material. Unauthorized use is illegal in most places. If you are unsure, do not run the tool. Read Legal before you transmit.

This page matches this master tree. The version string in the README, CHANGELOG.md, and docs/m5burner.json is Deepwater v0.8.0. There is no separate v0.8.1 firmware image in the repository. Notes that say “0.8.1 fork” mean this Deepwater tree: SaltyJack over Wi-Fi STA, and Rogue DHCP on the SoftAP, are in the image you flash today. The W5500 driver is not. The same text is in saltyjack-networking.md.

Four paths, and which one SaltyJack uses

The Cardputer-Adv radio is an ESP32-S3. It has 2.4 GHz Wi-Fi. It does not speak 5 GHz. SaltyJack does not gain a second radio because a hat is plugged in.

PathWho is the AP?What the Cardputer doesSaltyJack in this tree
Wi-Fi STA An authorized AP you already run Joins that AP as a client. lwIP attaches to the STA netif WIFI_STA_DEF. Works. DHCP Starve, Rogue DHCP (STA), Responder, and WPAD bind here.
SoftAP The Cardputer Open AP POSEIDON-SaltyJack. The Cardputer serves DHCP. Works, only as Rogue DHCP (AP). Not the STA path.
W5500 RJ45 Whatever is on the Ethernet segment Would be an SPI Ethernet netif, if a driver existed. Not implemented. Pinout only. hardware.html: “Not wired in this tree.”
ESP32-C5 Unrelated. The C5 is its own board. ESP-NOW satellite for 5 GHz, Zigbee, and 5 GHz PMKID. Never. SaltyJack does not send or receive through the C5.

Station mode means the Cardputer is a Wi-Fi client. It associates to an access point, takes a DHCP lease from that network’s server, and uses the address lwIP installed on the STA interface. Starve, rogue-STA, Responder, and WPAD all consult WiFi.status() / WiFi.localIP(). Starve also stops the DHCP client on WIFI_STA_DEF while it runs, because that client owns UDP/68. None of those tools open an Ethernet interface. None of them call the C5 command channel (c5_cmd_* over ESP-NOW).

Rogue DHCP (AP) is the contrast. It does not join the target AP. wifi_raw_ap_up("POSEIDON-SaltyJack") starts an open SoftAP on channel 1 (not hidden, up to 4 stations) through the raw-IDF helper. Arduino WiFi.softAP() crashes on the Bruce-pinned libraries this tree builds with, so the firmware does not use it. The AP address is lwIP’s default 192.168.4.1. The tool stops the IDF DHCP server on WIFI_AP_DEF and binds UDP/67 itself. Clients that join POSEIDON-SaltyJack are leased by the Cardputer, with the Cardputer as gateway and DNS.

0.8.1 vs future W5500

Lab notes call this fork “0.8.1”. The version string tagged in the README, CHANGELOG.md, and docs/m5burner.json is Deepwater v0.8.0. There is no v0.8.1 binary to flash. The table is what that image does today. The W5500 driver is the future row, not a hidden option in this tree.

Older roadmap, codex, and arsenal copy described a wired RaspyJack path as if it already ran. That was the intended design. It is not what this tree does.

Prerequisites

  • A Cardputer-Adv and this fork’s Deepwater image. Standalone units take poseidon-factory.bin at 0x0. Launcher units take the app-only image in the existing POSEIDON slot. Do not factory-flash a Launcher or Meshtastic layout. See the README Quick Start and Install.
  • Written authorization for the network you will join or stand up.
  • For How-to A: that AP’s SSID and passphrase. The S3 must associate and receive a non-zero IPv4 address. A WPA3-only, 802.1X, or PMF network that refuses this client never produces a STA lease, and SaltyJack stops at “Not connected.”
  • A microSD card if you want hash files. Responder and WPAD also print the capture on serial when the file cannot be opened.
  • Hats: one at a time, or none. STA SaltyJack uses the S3’s own Wi-Fi. Hydra and the CAP-LoRa1262 share SPI with the microSD (SCK 40, MISO 39, MOSI 14). Do not seat them together, and do not seat either in a session where a W5500 is attached.
  • The C5 is not a hat on that header. Unplug the Cardputer while you flash the C5 (How-to C), so the browser attaches to the C5.

How-to A — SaltyJack over Wi-Fi STA

This is the path that works now.

1. Flash this fork

Use the Deepwater binaries from this repository, not an upstream POSEIDON build and not a guessed “0.8.1” filename. The tagged image in-tree is v0.8.0.

  • Standalone / M5Burner: poseidon-factory.bin at offset 0x0.
  • M5Stack Launcher: poseidon-launcher.bin through Launcher’s installer.
  • The known dual-app development layout: poseidon-launcher-dual.bin into the POSEIDON slot only.

Browser flashing for the Cardputer is the ESP32-S3 target on docs/flash/ (desktop Chrome or Edge). Confirm the chip before you write. The C5 target on that page is How-to C.

2. Hats, one at a time

Power off. Remove a LoRa or Hydra hat you are not using. SaltyJack STA does not need a hat. Only one hat may be seated. Do not stack Hydra and LoRa.

3. Join the authorized network

The Cardputer has to be a client of that AP before Starve, Rogue DHCP (STA), Responder, or WPAD. Three menus open the same screen (feat_wifi_connect):

From the rootThenTitle
w Wi-Fin ConnectWIFI CONNECT
n Networkc ConnectWIFI CONNECT
s Systems Settings, then w Saved Wi-FiWIFI CONNECT

Starve and Responder say “via System > Connect.” There is no System item named Connect. Use one of the three paths above. System → Settings → Saved Wi-Fi is the closest match to that sentence.

On WIFI CONNECT:

  • n types a new SSID and password (Preferences namespace poseidon, keys ssid and pass).
  • c connects. An empty password, or an AP still selected from a Wi-Fi scan, forces a password prompt instead of replaying a stale secret.
  • x forgets the saved network.
  • Backtick goes back.

Connect uses wifi_lean_sta_init, then esp_wifi_set_config / esp_wifi_connect. It does not call Arduino WiFi.begin(), which can double-create the STA netif and reboot. It waits up to 15 seconds for an association and a non-zero address on WIFI_STA_DEF. Success shows CONNECTED plus IP, gateway, and mask. Failure shows FAILED and clears the saved password.

Stay associated. A raw SoftAP feature (portal, evil twin, beacon spam, Rogue DHCP (AP)) tears the STA netif down. Rejoin before the next STA SaltyJack tool.

4. Open SaltyJack

From the root menu press j. SaltyJack is its own screen, not a child of Network.

5. Tool order on an authorized LAN

Skip any step you are not authorized to run. Rogue DHCP (AP) is its own section. It is not step two of the STA flow.

  1. DHCP Starve (STA). Requires WL_CONNECTED and a non-zero localIP. The tool stops the STA DHCP client (the lease is already held; the client would consume UDP/68), binds UDP/68, and sends Discover + Request from random locally administered MACs. Counters: discover, offer, request, ACK, NAK. The server line is WiFi.gatewayIP() captured at start. NAK ≥ 20 shows pool exhausted. Backtick stops the flood, restarts the STA DHCP client, and shows totals. New legitimate clients cannot get an address while the pool is exhausted. Run this only on a lab LAN where that is the test.
  2. Rogue DHCP (STA). Requires WL_CONNECTED. Binds UDP/67. Discover gets an Offer, Request gets an ACK. Offered host suffixes are 100–150 on the subnet you joined, 16 clients maximum. Lease options: router and DNS are the Cardputer’s STA address, domain poseidon.lan (option 15), WPAD http://poseidon.lan/wpad.dat (option 252), lease 24 hours. The screen shows offers, ACKs, client count, and the last IP/MAC, or racing real server... until the first lease. This races the real DHCP server. It is not the SoftAP.
  3. Responder and/or WPAD NTLM. Both require WL_CONNECTED. They are separate menu items; opening one leaves the previous tool. The pairing that the menu describes is: rogue-STA (after starve, if that is in scope) so clients are told the Cardputer is gateway, DNS, and WPAD, then leave Responder or WPAD running.
    • Responder listens for LLMNR (UDP/5355, multicast 224.0.0.252), NetBIOS name service (UDP/137), and SMB (TCP/445). Name replies use the STA address. NTLMv2 material is appended to /poseidon/saltyjack/ntlm_hashes.txt in hashcat 5600 form user::domain:challenge:proof:blob. The module’s NetBIOS name is POSEIDON-SJ. The same line is printed on serial.
    • WPAD NTLM serves HTTP on port 80, including a PAC, then HTTP 407 with Proxy-Authenticate: NTLM. Captures append to the same file, with a # wpad from <client ip> comment. The address at the top of the screen is the STA address when association is up.
  4. NTLMv2 Crack (optional, offline). Reads ntlm_hashes.txt and ntlm_wordlist.txt under /poseidon/saltyjack/. Hits append to ntlm_found.txt. A default wordlist is seeded on first run. Enter skips a user. Backtick aborts. This tool does not check Wi-Fi.

Stop a live tool with backtick. Starve’s clean exit restarts the STA DHCP client. After a power cycle, Connect again and confirm a non-zero IP before the next run.

“Not connected”

The STA tools refuse to start when the S3 is not a client with a usable lease.

What the message is not

Not connected does not mean the W5500 cable is unplugged, and it does not mean the C5 is offline. Those paths are not consulted. It means the ESP32-S3 STA interface is down or has no IPv4 address.

  1. Join before the tool: Wi-Fi → Connect, Network → Connect, or System → Settings → Saved Wi-Fi. “System > Connect” is not a menu label.
  2. WIFI CONNECT must end on CONNECTED with a non-zero IP. FAILED drops the saved password; type it again.
  3. The AP has to be 2.4 GHz and has to accept this client. The S3 cannot join 5 GHz. A C5 on the bench does not give SaltyJack a 5 GHz STA.
  4. A SoftAP feature after Connect, including Rogue DHCP (AP), replaces the STA netif. Connect again.
  5. UDP bind failed, UDP :67 bind failed, or listener bind failed is a different fault: the interface was up and the port was busy. Leave the tool and try once. It is not the “Not connected” screen.
  6. A missing hash file can still have a serial line (---- SaltyJack NTLMv2 capture ---- or the WPAD banner). Seat the microSD. The directory is /poseidon/saltyjack/.

How-to B — W5500 RJ45

The module can be wired. This firmware does not drive it. docs/hardware.html marks the hat Not wired in this tree. src/features/saltyjack/saltyjack.h says attacks follow “whichever L2 lwIP is attached to — WiFi STA for now, W5500 wired once the SPI Ethernet hat is wired up.” There is no Ethernet.begin, no W5500 register setup, and no Ethernet netif. The jack will not move SaltyJack off Wi-Fi, and it will not clear “Not connected.”

Until a driver exists, use How-to A.

Pin table (Bruce / Cardputer-Adv)

SPI matches the microSD bus in src/sd_helper.cpp (SCK 40, MISO 39, MOSI 14, SD chip-select 12). Chip-select and interrupt are the Bruce-style W5500 assignment for this header. Reset is left open. The firmware does not claim these GPIOs for Ethernet.

SignalGPIONotes
SCLK40Shared HSPI clock (microSD and hats, not the display FSPI)
MOSI14Shared HSPI MOSI
MISO39Shared HSPI MISO
SCS1W5500 chip-select. Not the SD CS on GPIO 12.
INT2W5500 interrupt. Unused until a driver exists.
RSTNCDo not tie reset to a GPIO. Leave it open.
5V5VFull-size modules that expect 5 V, plus GND.
GNDGNDCommon ground with the Cardputer.
W5500 Mini is 3.3 V only

Do not power a Mini from the 5 V pin. That destroys the PHY. Use 3.3 V and GND for a Mini. Read the silkscreen on the board in your hand before you apply power.

Do not seat Hydra or LoRa at the same time

One hat. The header is shared.

  • CAP-LoRa1262 uses HSPI plus GPIO 3 (RST), 4 (DIO1), 5 (NSS), and 6 (BUSY). GNSS UART is GPIO 13 (MCU TX) and GPIO 15 (NMEA RX).
  • Hydra (CC1101 + nRF24) sits on the same HSPI pads: nRF24 CE on 4, CC1101 GDO0 on 5, nRF24 CS on 6, CC1101 CS on 13. GPIO 13 is also the LoRa-GNSS UART TX, so those two hats cannot be seated together.
  • The microSD already owns SCK 40, MISO 39, MOSI 14, and CS 12 on that HSPI bus (not the display’s FSPI).
  • A W5500 on SCS 1 / INT 2 still shares SCK, MOSI, and MISO with the card and with those hats.

Seating Hydra or LoRa with the W5500, or seating Hydra and LoRa together, fights chip-select and the SPI lines. Remove them before you attach the Ethernet module. The Feather nRF52840 hat is also mutually exclusive with LoRa / Hydra. It is not part of SaltyJack.

What you can and cannot expect

  • You can build the cable to the table and leave it off the network until firmware exists.
  • You cannot run starve, rogue DHCP, Responder, or WPAD over the jack on this image.
  • You cannot clear “Not connected” with the cable.
  • A later image would have to create an lwIP netif on the W5500 and teach the tools to accept it. That code is not here. The v0.4 roadmap line that described wired parity did not land in this tree.

How-to C — ESP32-C5 TRIDENT

The C5 is a second board. It talks to the Cardputer over ESP-NOW (magic POSE) on Wi-Fi channel 1. It is how this fork reaches 5 GHz Wi-Fi, 802.15.4 / Zigbee, and 5 GHz PMKID. The S3 cannot transmit or capture on 5 GHz alone. The C5 menu is root 5 (C5 nodes), not j (SaltyJack).

SaltyJack never routes through the C5. A paired C5 does not join a LAN, does not create a STA lease, and does not change the “Not connected” check.

5 GHz deauth and PMKID capture are transmissions and credential capture. Same rule: your equipment, or written permission.

Flash the C5, not the Cardputer

  1. Unplug the Cardputer from USB. If both boards are plugged in, Web Serial often opens the S3. You will write the wrong image, or write C5 offsets onto the Cardputer.
  2. Plug in only the ESP32-C5.
  3. Open docs/flash/ in desktop Chrome or Edge. Firefox, Safari, and phone browsers have no Web Serial. Desktop Opera works on that page too.
  4. Set Target to TRIDENT — C5 Satellite (ESP32-C5). Do not leave the ESP32-S3 target selected.
  5. Connect, then flash. Three parts, under docs/flash/bin/trident-c5/:
OffsetFile
0x2000bootloader.bin
0x8000partition-table.bin
0x10000poseidon_c5_node.bin

The flasher pins the C5 to 4 MB, DIO, 80 MHz. Automatic size detect on this chip falls back to about 1 MB and the write dies past 0x100000.

CLI equivalent, from docs/flash/:

esptool --chip esp32c5 -p <PORT> --baud 460800 write_flash \
  --flash_mode dio --flash_freq 80m --flash_size 4MB \
  0x2000   bin/trident-c5/bootloader.bin \
  0x8000   bin/trident-c5/partition-table.bin \
  0x10000  bin/trident-c5/poseidon_c5_node.bin

Building from source is c5_node/ with ESP-IDF (this firmware targets 5.5.4). See c5_node/README.md. The bins above are what the web flasher writes.

Auto-pair, then C5 → Status

There is no PIN and no SaltyJack setting. After boot the C5 broadcasts an ESP-NOW HELLO about every 5 seconds. The Cardputer locks ESP-NOW receive to channel 1 so those HELLOs are not missed.

  1. Power the Cardputer again and power the C5 nearby.
  2. Root menu 5 C5 nodes.
  3. s Status.

Status calls c5_begin() and lists peers. With no HELLO yet: NO C5 ONLINE, power on your C5 node., it broadcasts HELLO every 5s., will auto-connect. When a HELLO lands the screen switches to ONLINE and the peer name. The corner dot is green when any C5 is online and red when none are. P pings every peer. S broadcasts STOP.

Scan 5G+2G, Zigbee sniff, Deauth 5G, PMKID 5G, and Nuke 5G send ESP-NOW commands to that peer. They need a peer online. They do not configure SaltyJack, and SaltyJack does not call them.

SoftAP rogue DHCP

Rogue DHCP (AP) is not How-to A and not the C5. From SaltyJack (j) open Rogue DHCP (AP).

  • SSID POSEIDON-SaltyJack, open, channel 1.
  • Address 192.168.4.1 unless lwIP’s AP default has changed.
  • The Cardputer is the DHCP server. Lease options match the STA rogue tool (gateway, DNS, poseidon.lan, option 252).
  • Clients must join that SSID. They are not stations of your existing AP.
  • Failure is AP setup failed / check heap / radio, often after other Wi-Fi features have fragmented the heap. Reboot and run this tool first if you need the SoftAP.
  • Starting it drops the STA session. Responder and WPAD still require WL_CONNECTED, so they do not follow onto the SoftAP in this tree. Their menu items still show “Not connected” if the Cardputer is only hosting POSEIDON-SaltyJack. The AP tool’s DHCP options do point clients at the Cardputer; the listener tools do not switch interfaces to match.

Use the SoftAP when the test is “clients that associate to an open lab AP we operate.” Use STA when the test is “the Cardputer is already a client on an authorized LAN.”
